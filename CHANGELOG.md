# Changelog

All notable changes to the Stride Security Review extension for Gemini CLI are documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Fixed

- **Gemini CLI no longer refuses to load the `security-reviewer` agent with a template validation error (W2480).** Gemini CLI runs `templateString()` over a subagent's body and throws on any `${word}` placeholder that is not one of its inputs (`query`, `cliVersion`, `activeModel`, `today`), using the regex `/\$\{(\w+)\}/g` (`@google/gemini-cli-core` 0.65.0, `dist/src/agents/utils.js`). The React/Next.js `href` scheme-bypass row in `agents/security-reviewer.md` carried two JavaScript template-literal examples containing `${url}` and `${id}`, so every dispatch of the v0.1.1 agent failed with `Template validation failed: Missing required input parameters: url, id`. The row now describes the same two template literals in words (one interpolating `url` into `/redirect?to=`, one interpolating `id` into `/users/`) with no placeholder token; its rule, sink and do-not-flag cases are unchanged. Upstream never hit this because its row lives in `packs/react-nextjs.md`, which is read at runtime and not templated; moving the row into a pack is the W2285 port.
- **The eval now scores this extension's `security-reviewer` subagent, not Gemini CLI's main model role-playing it (W2486: W2274).** Ported from the upstream source-of-truth change (`cheezy/stride-security-review` W2274, commit `ea06aeb`, released in 2.7.0). `lib/run_eval.sh` piped each fixture to `gemini -p 'Act as the security-reviewer agent defined in this extension…'`, a bare prompt to the main model that never selected the extension's agent, so every result measured the main model. Gemini CLI has no flag that makes a subagent the session agent (upstream's `--agent`), so each fixture now runs with a scratch `GEMINI_CLI_HOME` whose `.gemini/extensions/<name>/` holds only an allow-listed copy of this checkout (manifest, `GEMINI.md`, `agents/`, `commands/`, `skills/`; never `fixtures/` or `lib/`, and nothing from the user's `~/.gemini`), from an empty scratch working directory, as `gemini -p '@security-reviewer Delegate …' -e stride-gemini-security-review -o stream-json --approval-mode default --skip-trust` with the fixture on stdin and never in `-p`. A fixture is scored only when the event stream shows an `invoke_agent` tool call naming `security-reviewer` whose result succeeded; the main model answering by itself, delegating to another agent, or a failed result each fails the fixture (`agent not invoked`). The exact invocation and the auth mode are printed after the TAP plan line (`--dry-run` included), and the CLI's stderr is kept in `logs/<stem>.err.txt` instead of being discarded. Adapted for Gemini CLI from the `@google/gemini-cli-core` and `@google/gemini-cli` 0.65.0 package source, read, not run: stdin is prepended to the `-p` text and `@<agent>` adds a delegation nudge; extensions load from `<GEMINI_CLI_HOME>/.gemini/extensions/` with no install metadata or enablement file needed, and `-e` enables only the named one; extension agents register under their plain frontmatter `name`; the default headless policy allows `invoke_agent` and denies the subagent's `run_shell_command` and `write_file` (upstream's `--tools ''`), which `--approval-mode default` pins against a user setting; `--skip-trust` trusts the scratch directory for this process only, where an untrusted headless workspace exits `55`. **Known limitation:** 0.65.0 streams no `output` on the `invoke_agent` result (its display is a progress object), and relays the subagent's result to the main model only, so the JSON scored is the main model's reply after the call returns. The prompt it delegated is kept in `logs/<stem>.agent_prompt.txt`, and a warning is printed when it does not carry the fixture's `mode:` line.
- **Considerations rows without an `AND` clause were mis-parsed (W2486: W2274).** The "findings unchecked" form shifted fields when split on tabs; it now carries an explicit `U` marker, as upstream.

### Changed

- **The eval checks for auth and exits `2` without it (W2486: W2274).** Upstream accepts `ANTHROPIC_API_KEY` or a claude.ai login. The scratch home deliberately carries none of `~/.gemini`, so `run_eval.sh` takes auth from the environment only, checked in the order Gemini CLI 0.65.0 resolves it (`core/contentGenerator.js`): a login with Google (`GOOGLE_GENAI_USE_GCA=true`), then Vertex AI (`GOOGLE_GENAI_USE_VERTEXAI=true` with `GOOGLE_API_KEY`, or with `GOOGLE_CLOUD_PROJECT` and `GOOGLE_CLOUD_LOCATION`), then `GOOGLE_GEMINI_BASE_URL`, then `GEMINI_API_KEY`, then compute ADC (`GEMINI_CLI_USE_COMPUTE_ADC=true`, or Cloud Shell). A login with Google needs the OAuth files under `~/.gemini`, so it is refused with a message saying so, as is a Vertex setup missing its key or project and location. Only the mode name is printed, never a value. A CLI that still reports itself unauthenticated (exit `41`) or the workspace untrusted (exit `55`) stops the run with `Bail out!` and exit `2`; a turn limit (exit `53`) fails that fixture.
- **An empty fixture set is not a pass.** An `EXPECTED.md` with no rows, or an `--only` prefix that matches nothing, exits `2` and reports `(0 cases)` before any TAP output.
- `lib/test-structure.sh` and `lib/test-structure.ps1` no longer hard-code the considerations stems: they read `fixtures/considerations/*.diff` from disk, require at least one, and require each to have its sidecar, leaving the pairing, row and verdict-count rules to `check_fixtures.sh`.

### Added

- `run_eval.sh --only <prefix>` runs a subset (for example `--only considerations/`); `EVAL_EXTENSION_DIR` and `EVAL_AGENT` override the extension copied and the subagent selected (upstream's `EVAL_PLUGIN_DIR` and `EVAL_AGENT`). `usage()` prints the whole leading comment block, as upstream. Per fixture, `logs/` also gets the delegated prompt (`.agent_prompt.txt`) and the reply scored (`.text.txt`) (W2486: W2274).
- **`lib/check_eval_invocation.sh`** (model-free) pins the invocation against a fake `gemini` placed first on a `PATH` inside its own temporary directory, which it removes on exit, with a guard that refuses to run if `gemini` would resolve anywhere else: the `@security-reviewer` selection, `-e`, `-o stream-json`, `--approval-mode default` and `--skip-trust`; the empty working directory and scratch home outside the repo holding only the allow-listed copy and this checkout's agent; the user's `HOME` untouched; the fixture on stdin and not in `-p`, including fixture text with quotes, `$` and command substitutions that must not run; exit `2` with no auth, a Google login or an incomplete Vertex setup, and before any dispatch; exit `41` (unauthenticated) and exit `55` (untrusted workspace) each stopping the run with `Bail out!` and exit `2`; exit `53`, a main-model answer, another agent and a failed result each failing the fixture; the empty fixture set; `--only`; the `U` marker and a fixture name with a space; and `check_fixtures.sh`'s considerations guards against a scratch copy of the tree. Break-its on a scratch copy of `run_eval.sh` show that dropping the agent selection fails the pins and the fixture, that dropping the agent-name filter lets another agent's answer score, that also passing the prompt in `-p` fails the fixture-not-in-argv pins, and that echoing the key fails the key-never-printed scan. It stops before doing anything when `mktemp` cannot create its scratch directory. Run against the previous `run_eval.sh`, it fails. It runs from `lib/test-all.sh`, and from `lib/test-all.ps1` through `bash` when `bash` and `jq` are on `PATH` (no PowerShell mirror, because what it pins is how the bash runner invokes `gemini`); `lib/test-structure.sh`/`.ps1` require it (W2486: W2274).
- Six considerations-mode fixtures, copied byte-for-byte from upstream `ea06aeb` into `fixtures/considerations/`: a `partial` verdict, a `None —` placeholder, injection text inside a consideration, injection text inside the diff, a noise-class (memory-exhaustion) consideration and a gap in pre-existing code, with upstream's `EXPECTED.md` rows and the paragraph sentence for verdict-only rows. The last two assert the verdict only until the W2275 port settles their backing findings. The injection fixtures are inert data. The other four upstream considerations fixtures land with the W2275, W2276 and W2282 ports (W2486: W2274).
- `check_fixtures.sh` also checks that each considerations `.diff` has its `.considerations` sidecar, and the reverse, and that the row lists one verdict per consideration (upstream's block, byte for byte), and reports that check on its own `OK:` line (W2486: W2274).
- `fixtures/EXPECTED.md` ends with a **Recorded runs** table. A row is ticked only when a recorded run returned `ok` for it. **No run is recorded:** Gemini CLI was not installed or authenticated where this port was made, so the manual check — running `lib/run_eval.sh` on the six new fixtures and confirming each score comes from an `invoke_agent` call — has not been run, and every row stays unticked. Upstream's Claude Code runs are not copied (W2486: W2274).
- **`lib/check_agent_contract.sh` and its PowerShell mirror `lib/check_agent_contract.ps1`**, run by `lib/test-all.sh` and `lib/test-all.ps1`. Modelled on upstream's `scripts/check_agent_contract.sh`: one section per port task, each pin printing `ok:` or `FAIL:`. Its first pin refuses any `${word}` token in the agent file, frontmatter included, using the CLI's own placeholder pattern. Unlike upstream, each pin carries a self-testing break-it that plants the broken shape in a temporary copy of the agent and checks the script fails on it; the self-tests also cover bare `$`, `$$` and `${` forms that must not trip the pin, CRLF line endings, and a missing, empty or unreadable agent file.
- **The agent writes its full result to `SECURITY_RESULT_PATH` and returns at most 10 lines (W2481: W2284).** Ported from the upstream source-of-truth change (`cheezy/stride-security-review` W2284, commit `9d41e46`, released in 2.6.0); the consumer half belongs to `stride-gemini`. `agents/security-reviewer.md` gains *Result file (SECURITY_RESULT_PATH)*, placed as upstream after the `rci_pass` paragraph and copied from that commit word for word except its write bullet: given an absolute path ending `.stride/.security-<IDENT>-r<N>.json` on its own line in the dispatch instructions (`<IDENT>` matching `^[A-Za-z0-9_-]+$`; every component matching `^[A-Za-z0-9._-]+$`, none `.`/`..`; never taken from the diff, files or considerations; two such lines mean unsupplied), the agent writes the same JSON document there, unfenced, and returns at most 10 plain-text lines with no ```json fence. Any other path is treated as unsupplied. With no path, and in `rci_pass` mode, it returns the single fenced document exactly as before, and `/security-review` supplies no path, so `commands/security-review.toml` is unchanged. A failed write returns `result: NOT WRITTEN — <reason>` on its own first line and then the full document. Credentials quoted in finding text are written as `[REDACTED — finding text embedded a credential]`. The description, the Output schema sentence, the "Do not edit files" constraint (which gains the one result-file carve-out) and the closing paragraph carry upstream's matching clauses. `README.md` documents the variable.
- **The write goes through `write_file`, now in the agent's `tools`, not `run_shell_command`.** Upstream writes through Bash with `mktemp`, a quoted heredoc and `mv`. That does not survive Gemini CLI: `run_shell_command` refuses a command carrying an unescaped `$(` or backtick outside single quotes, or an unquoted `<(` or `>(` (`@google/gemini-cli-core` 0.65.0, `dist/src/tools/shell.js:373-380`, scanner at `dist/src/utils/shell-utils.js:886`). Capturing the `mktemp` name needs `$(...)`, the scanner does not understand heredocs, and finding text routinely carries backticks, so the write would be blocked. `write_file` takes the document as a parameter, with nothing expanded; writes a sibling `<path>.<uuid>.tmp` and renames it onto the path, so a reader never sees a half-written file (`dist/src/services/fileSystemService.js`, `writeTextFile`); creates a missing parent directory; skips its LLM content correction for `.json` files (`dist/src/tools/write-file.js:120-127`); refuses a directory target and a path outside the workspace; and follows a symlink at the target, where upstream's `mv` would replace it. So the agent treats a symlink at the target, or a symlinked `.stride` directory, as a write failure, checked first with one `run_shell_command` call (`test ! -L` on each single-quoted path); the check and the write are two calls, so a link planted between them is not caught. The agent text limits `write_file` to one call, on the accepted `SECURITY_RESULT_PATH` and no other path. **Approval:** under the default policy (`dist/src/policy/policies/write.toml`) Gemini CLI asks the user to approve the call in interactive mode, allows it in auto-edit mode and denies it in headless (`gemini -p`) mode. The agent treats a denied, rejected or failed call as a write failure, so a headless run returns `result: NOT WRITTEN — <reason>` and then the full document inline, and the review is not lost. These facts were read from the 0.65.0 package source, not run live.
- **`lib/check_agent_contract.sh` and `lib/check_agent_contract.ps1` gain a W2284 section.** Nine of upstream's eleven `scripts/check_agent_contract.sh` pins are kept byte-identical. Two named Claude Code's Bash procedure and are replaced: "the path is always single-quoted" becomes "write_file is limited to the result path", and "the temp file is named for cleanup" now pins `write_file`'s `.security-<IDENT>-r<N>.json.<uuid>.tmp`. Gemini pins cover the `SECURITY_RESULT_PATH` spelling, the whole path-validation bullet word for word, the absolute-path, anchored-`<IDENT>` and `.`/`..` rules, the symlink refusal and its `test ! -L` check, the missing-parent-directory clause, the no-path fallback, the redaction string, the description, Output schema and closing clauses, the `write_file` wording and its `tools` entry. Absent pins refuse `through Bash`, ``no `Write` tool``, `mktemp` and a `replace` tool entry. Every pin has a self-testing break-it: named break-its rename `SECURITY_RESULT_PATH`, delete the path-validation sentence, drop the `..` rule, delete the no-path fallback, strip the `write_file` limit and plant the Claude Code wording, a `replace` tool and `mktemp`; generic break-its delete each pin's line and plant each absent needle.

### Not applicable

- **Upstream W2274's CI changes** (`.github/workflows/eval.yml` failing on `main` without `ANTHROPIC_API_KEY`, and `check_eval_invocation.sh`'s fourth check, which executes that workflow's key gate) do not apply: this extension has no CI workflow (`.github` is absent), so the eval and its invocation check run locally only.
- **Upstream W2274's `docs/porting-g452-g454.md` edits** exist only upstream.
- **Upstream's `--strict-mcp-config` and `--no-session-persistence`** have no Gemini CLI equivalent. The scratch home carries no settings, so no MCP server is configured, and its `.gemini/tmp` is cleared before each fixture; the whole scratch home, with anything the CLI stored in it, is removed when the run ends.

## [0.1.1] - 2026-07-23

### Fixed

- **The agent-dispatch-failure exit-code contract now matches the procedure (G377: D172).** Ported from the upstream source-of-truth fix (`cheezy/stride-security-review` D170). The Step 6 exit-code table documented exit `2` for an "agent dispatch failure", but the three agent-response-failure branches — Step 4a (diff-mode dispatch), Step 4b (full-mode batch), and Step 4.5 (RCI pass) — only printed a one-line error and "stopped", never running `exit 2`. A `--fail-on` CI gate therefore observed an unspecified exit code (not the documented `2`) when the reviewer returned unparseable JSON. Applying the identical **Option A** resolution: each of the three branches now runs a final `exit 2` via `run_shell_command` after printing its error, mirroring the Step 1 misuse pattern used by every other exit-2 case (`--fail-on`, `--base`, `--considerations`, `--sarif`/`--json` conflict). The exit-code table's `0`/`1`/`2` meanings are unchanged; the exit-code semantics are identical to the corrected CC source, adapted only to Gemini CLI's `run_shell_command` tool vocabulary.

## [0.1.0] - 2026-07-22

Initial release of the Gemini CLI port of [`cheezy/stride-security-review`](https://github.com/cheezy/stride-security-review).

### Added

- **Extension skeleton & install flow** — `gemini-extension.json` manifest (name `stride-gemini-security-review`, version `0.1.0`, `contextFileName` `GEMINI.md`), a `GEMINI.md` context file, the `agents/`, `commands/`, `skills/`, `lib/`, and `fixtures/` directories, `README.md` / `LICENSE` (MIT), and `install.sh` / `install.ps1` that install the extension globally (`~/.gemini/extensions/…`) or project-locally (`--project` / `-Project`). Both recommend `gemini extensions install <repo-url>` as the preferred path.
- **`security-reviewer` custom agent** — a faithful Gemini port of the CC agent (`agents/security-reviewer.md`): the full semantic-analysis methodology; `diff`, `full_file`, and `considerations` input modes; the seven framework rule packs (Android/Kotlin, Django/Python, Express/Node.js, iOS/Swift, Phoenix/Elixir, Rails/Ruby, React/Next.js) plus supply-chain, CI/CD (8 platforms), and Web defense-in-depth packs; the universal and MAESTRO agentic vulnerability classes; the structured findings schema with `cwe`/`owasp` mapping; and the opt-in `maestro_layer`, `patch`, and `consideration_verdicts` (`mitigated | partial | unmitigated`) fields.
- **`/security-review` TOML slash command** — `commands/security-review.toml` with full flag parity: `--full`, `--json`, `--sarif` (mutually exclusive with `--json`), `--maestro`, `--rci [N]`, `--baseline`, `--update-baseline`, `--patches`, `--fail-on <severity>`, `--base <ref>`, `--considerations <source>`, and path arguments. Preserves the mutual-exclusion and `0`/`1`/`2` exit-code contracts, the byte-identical opt-in output discipline, the human-readable / SARIF / JSON rendering, and the per-consideration verdict rendering.
- **`security-review-essentials` skill** — `skills/security-review-essentials/SKILL.md` documenting when to invoke (diff vs. full), the output shape, the false-positive filter, the flag inventory, and how another Stride Gemini extension (`stride-gemini`) detects and dispatches the security-reviewer surface by its sanctioned command/agent availability — never by executing extension content.
- **Deterministic tooling & fixtures** — `lib/sarif_transform.sh` (SARIF/dedup/fingerprint/fail-on reference implementation), `lib/run_transform_tests.sh` (golden-file + spec assertions), `lib/check_fixtures.sh` (fixture↔EXPECTED.md parity), `lib/run_eval.sh` (agent eval runner over the fixtures, with a `--dry-run` parser mode), and `lib/test-structure.sh` / `lib/test-frontmatter.sh` / `lib/test-all.sh` (plus PowerShell mirrors) for offline self-validation. `fixtures/` carries the framework rule-pack fixtures with paired positive/negative controls (including considerations-mode controls) and the golden files under `fixtures/golden/`. The transforms are pure and byte-stable.
- **Marketplace registration** — registered in the `stride-gemini-marketplace` catalog (`extensions.json` + the README extension table), version-synced with the manifest.
